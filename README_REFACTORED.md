# Tomten Project - Refactored

A Raspberry Pi-based interactive storytelling system with synchronized audio and visual hardware control.

## Project Structure

```
tomten/
├── main.py              # Main orchestrator (entry point for production)
├── test_scenario.py     # Testing utility with visualization
├── hardware.py          # GPIO/Hardware control module
├── audio.py            # Audio/Sound management module
├── parser.py           # Scenario file parser
├── scenarious/         # Scenario files
│   ├── example.yaml    # YAML format example
│   ├── example.json    # JSON format example
│   ├── door.txt        # Legacy text format
│   └── ...
└── sounds/             # Audio files directory
    ├── cat.run.ogg
    ├── door.open.ogg
    └── ...
```

## Architecture

### Modular Design

The refactored code is split into focused modules:

- **hardware.py**: Hardware abstraction layer
  - `DoorController`: Servo motor control with easing functions
  - `LightController`: GPIO light control
  - `HardwareManager`: Centralized hardware coordination
  - `EasingFunctions`: Smooth animation curves

- **audio.py**: Audio management
  - `SoundLibrary`: Sound file loading and caching
  - `SoundPlayer`: Synchronized playback

- **parser.py**: Scenario parsing
  - `ScenarioParser`: Multi-format scenario parsing
  - `ScenarioFormat`: Action definitions
  - `Action`: Action data structure
  - `TimingSpec`: Timing synchronization

- **main.py**: Production orchestrator
  - `ScenarioExecutor`: Executes scenarios with synchronization

- **test_scenario.py**: Testing and visualization
  - `ScenarioTester`: Test scenarios without hardware
  - `SimpleVisualizer`: Timeline visualization
  - `MockHardwareDisplay`: Hardware simulation

## Improved Scenario Syntax

### Features

✓ **Human-readable** - Clear, intuitive format  
✓ **LLM-compatible** - Easy for AI to generate  
✓ **Flexible timing** - Relative and absolute timing  
✓ **Parametrized** - Customize action behavior  
✓ **Multi-format** - YAML, JSON, and legacy text  

### Timing Specifications

Actions can be timed relative to previous actions:

```
default        → Start after previous action ends (default)
start+2        → Start 2s after previous action started
finish-1       → Start 1s before previous action ends
absolute:5.5   → Start at absolute time 5.5s
```

### Format Examples

#### YAML Format
```yaml
- light.on

- door.open
  params:
    duration: 2.0

- guest.doorbell

- door.close
  params:
    duration: 0.5
    
- light.off
  timing: "finish+1"
```

#### JSON Format
```json
{
  "actions": [
    {"name": "light.on"},
    {
      "name": "door.open",
      "params": {"duration": 2.0}
    },
    {"name": "guest.doorbell"},
    {
      "name": "door.close",
      "params": {"duration": 0.5}
    },
    {
      "name": "light.off",
      "timing": "finish+1"
    }
  ]
}
```

#### Text Format (Legacy)
```
light.on
door.open
guest.doorbell
door.close
light.off
```

## Usage

### Production Execution

```bash
python main.py scenarious/example.yaml
python main.py scenarious/example.json --hardware
```

### Testing & Visualization

```bash
# Full test with visualization and audio simulation
python test_scenario.py scenarious/example.yaml

# Test without audio
python test_scenario.py scenarious/example.yaml --no-audio

# Test without hardware simulation
python test_scenario.py scenarious/example.yaml --no-hardware

# Test without visualization
python test_scenario.py scenarious/example.yaml --no-vis
```

## Available Actions

### Sound Actions
- `cat.run` - Cat running sound
- `cat.meow` - Cat meowing
- `tomten.walk` - Tomten walking
- `guest.doorbell` - Doorbell ring
- `guest.snowwalk` - Walking in snow

### Hardware Actions
- `light.on` - Turn light on
- `light.off` - Turn light off
- `light.toggle` - Toggle light state
- `door.open` - Open door (params: `duration`, default 2.0s)
- `door.close` - Close door (params: `duration`, default 0.33s)

### Combined Actions
Actions can have both sound and hardware components that execute simultaneously.

## Configuration

### Hardware Parameters

**Door Movement:**
```python
door.open
  params:
    duration: 2.0        # Seconds to fully open
```

```python
door.close
  params:
    duration: 0.5        # Seconds to fully close
```

**Servo Pulse Widths** (in `hardware.py`):
```python
DoorController(
    closed_pulse=1500,   # PWM when door closed
    open_pulse=700,      # PWM when door open
)
```

**Light GPIO Pin** (in `hardware.py`):
```python
LightController(pin=17, invert_logic=True)
```

## Development Notes

### Adding New Actions

1. **Define action in `parser.py`:**
```python
self.actions['my.action'] = {
    'sound': 'my_sound.ogg',
    'hardware': 'hardware.action'
}
```

2. **Implement hardware handler in `hardware.py`:**
```python
def execute_action(self, action_type: str, **kwargs):
    if action_type == 'hardware.action':
        # Your implementation
```

3. **Use in scenarios:**
```yaml
- my.action
  params:
    custom_param: value
```

### Testing New Scenarios

Always test with `test_scenario.py` first:

```bash
python test_scenario.py scenarious/my_scenario.yaml
```

This provides visual feedback and mock hardware simulation without risking GPIO damage.

## Troubleshooting

### Sound not playing
- Check sound file exists in `sounds/` directory
- Verify file format is supported (OGG, WAV)
- Check volume levels

### Door not moving
- Verify GPIO pin and servo connections
- Check PWM frequency (should be 50Hz)
- Test servo directly with known working code

### Timing issues
- Use `test_scenario.py` to visualize timing
- Check sound file durations match expectations
- Verify `start_time` calculations in parser output
